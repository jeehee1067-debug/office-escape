# S1FA 방탈출 : 분석기술팀 탈출 대작전

40명 이상이 동시에 접속해 즐기는 **사내 이벤트용 실시간 방탈출 웹게임**입니다.
GitHub Pages(정적 호스팅) + Firebase Realtime Database 로 동작하며, 서버 코드가 필요 없습니다.

> 디자인은 포켓몬(GBA) 스타일을 참고했습니다. 방 배경과 캐릭터는 준비된 그림 파일을 쓰고,
> 그림이 없으면 코드에서 직접 찍은 도트 그래픽으로 자동 대체됩니다.

---

## 0. 행사 전 체크리스트

**게임 안에서 확인할 수 있습니다.** 관리자로 로그인하면 자동으로 서버를 점검하고,
문제가 있을 때만 알려줍니다. 언제든 관리자 패널 → **🧪 행사 준비 점검** 으로 다시 볼 수 있습니다.

| | 할 일 | 어디서 | 확인 방법 |
|---|---|---|---|
| 1 | `database.rules.json` 내용을 규칙 탭에 붙여넣고 **게시** | Firebase 콘솔 | 점검의 **보안 규칙 게시됨 / 관리자 키 숨겨짐** ✅ |
| 2 | **관리자로 한 번 로그인** (비밀번호가 이때 고정되고 배점표가 올라감) | 게임 화면 | 점검의 **문제 배점표 등록됨 / 점수 위조 차단** ✅ |
| 3 | **전체 데이터 초기화** 한 번 (테스트 기록·예전 형식 데이터 정리) | 관리자 패널 | 점검의 **예전 데이터 정리됨** ✅ |
| 4 | 참가자 안내 링크 공유 | — | — |

여섯 항목이 모두 ✅ 면 준비가 끝난 것입니다. ❌ 가 있으면 그 줄에 해결 방법이 함께 나옵니다.

> **비밀번호**는 코드에 없습니다. 서버에 **처음 로그인할 때 입력한 값**이 그대로 고정됩니다.
> 바꾸려면 콘솔에서 `v2/config/adminKey` 를 지우고 새 비밀번호로 다시 로그인하세요
> (그 사이에는 아무나 첫 로그인으로 관리자가 되니 바로 이어서 하세요).
>
> **문제은행의 배점을 바꾸면** 관리자가 다시 로그인해야 서버 배점표가 갱신됩니다.
> 안 하면 참가자의 정답이 서버에서 거부됩니다 — 점검의 *문제 배점표 등록됨* 이 ❌ 로 알려줍니다.

## 2. Firebase 연결 (40명 동시 접속용)

1. [Firebase 콘솔](https://console.firebase.google.com/) 에서 프로젝트를 만들고
   **Realtime Database** 를 생성합니다.
2. `assets/js/net.js` 상단의 `firebaseConfig` 를 내 프로젝트 값으로 교체합니다.
3. **Realtime Database → 규칙** 탭에 `database.rules.json` **파일 내용 전체**를 붙여넣고 **게시**합니다.
   (규칙 파일은 순수 JSON 이라 그대로 붙여넣으면 됩니다. 설명은 `database.rules.md` 에 있습니다.
   터미널이 편하면 `node tools/print-rules.js` 로 같은 내용을 출력할 수 있습니다.)
4. 행사 전에 한 번, 콘솔의 **데이터** 탭에서 `v2` 노드를 지워 깨끗한 상태로 시작하세요.
   (테스트 중 쌓인 기록·참가자와 예전 형식의 데이터를 정리합니다.)
5. 관리자로 **한 번 로그인**하세요. 그때 문제은행의 배점표가 서버(`v2/bank`)에 올라가며,
   규칙은 이 표와 다른 점수를 거부합니다. **문제은행 배점을 바꾸면 관리자가 다시 로그인**해야 합니다.

### 규칙이 지켜주는 것 (기록 위·변조 방지)
| 대상 | 규칙 |
|---|---|
| 문제 정답 기록 `runs/*/rooms/*/solves/*` | **한 번 쓰면 수정·삭제 불가** (`!data.exists()`), 배점은 서버에 올린 문제은행 배점표와 같은 값만, 기록 시각은 서버 시각만 허용 |
| 방 종료 기록 `runs/*/rooms/*/done` | **한 번만 기록 가능**, 소요시간·보너스 상한 검증 |
| 오답 횟수 `wrong` | 증가만 가능(줄일 수 없음) |
| 게임 진행 제어 `global`, 데이터 삭제 | **관리자 키를 아는 사람만** 쓰기 가능 |
| 관리자 키 `config` | 클라이언트가 **읽을 수 없음** (`.read: false`) |

즉 참가자가 개발자도구로 `localStorage` 를 고쳐도 점수·시간은 바뀌지 않습니다.
화면 표시값은 매번 **서버 기록으로부터 다시 계산**됩니다.

## 3. 게임 구성

| 구간 | 내용 |
|---|---|
| 대기실 | 캐릭터 선택 → 근무지(SR3/S1L) → 이름 입력 → 입장. 접속한 사람들이 도트 캐릭터로 함께 서 있음 |
| 1관 | EFA1 파트 — 서류박스 치우기 / 모니터 순서대로 켜기 / 파트장님과 대화 |
| 2관 | EFA2 파트 — 케이블 색 맞춰 잇기 / 서랍 3칸 중 진짜 찾기 / 컵 집어 커피 내리기 |
| 3관 | PFA·VSEM — 모니터 얼룩 문질러 닦기 / VSEM 배율 맞추기 / 시편 트레이에 옮기기 |
| 4관 | 캔틴룸 — 컵 더미 치워 금고 번호 찾기 → 금고 키패드 열기 / 자판기 버튼 순서 |
| 중간 대기실 | 방을 마칠 때마다 이 방 점수·누적 점수·실시간 순위 확인 |
| 결과 발표 | 시상대 + 방별 기록 + 전체 순위, CSV 내보내기 |

- 방마다 **5분**, 총 **4개 방 = 20분**.
- 각 방에는 **문제 6개**가 준비돼 있고 그중 **3개**가 출제됩니다.
  팀이 구성되어 있으면 **팀마다 다른 조합**이 나와 컨닝이 어렵습니다.
- **낚시 요소**: 화분·소화기·규격집·다이어리 등에는 그럴듯한 숫자가 적혀 있지만
  전부 가짜입니다. **감점은 없고 시간만 버립니다.**
  (되살리려면 `data.js` 의 `TRAP_PENALTY` 를 0 이 아닌 값으로)

### 점수 — 40명이 전부 다른 등수로 갈리게

| 항목 | 값 | 왜 이렇게 |
|---|---|---|
| 일반 문제 | **6,000** | 난이도별로 **고정**. 팀마다 나오는 조합이 달라도 만점이 같아야 공정합니다 |
| 근무지 전용 | **8,000** | 〃 |
| 고난도 | **10,000** | 〃 |
| ⚡ 속도 점수 | **정답 순간 남은 1초당 +5** (최대 1,500) | 같은 문제를 맞혀도 **초 단위로 점수가 갈립니다** |
| 방 클리어 보너스 | 남은 시간 비례 최대 **3,000** | 3문제를 다 풀고 방을 나갔을 때만 |
| 오답 | **−1,000** | |
| 함정(낚시) | **없음** (`TRAP_PENALTY: 0`) | 시간만 버립니다. 감점은 순위를 가르는 데 거의 기여하지 않았습니다 |

- 한 팀의 만점은 **126,000점** (배점 96,000 + 속도 18,000 + 클리어 12,000)으로 **모든 팀이 같습니다.**
- 예전에는 배점이 6,500~10,000 으로 제각각이라 **팀마다 만점이 최대 2,000점 달랐고**,
  점수가 전부 500 단위라 같은 문제를 푼 사람끼리 **점수가 똑같이 겹쳤습니다.**
  이제 속도 점수가 1초 단위로 붙어 동점이 거의 나오지 않습니다.
- 그래도 같은 점수가 나오면 **총 소요 시간 → 맞힌 단서 수 → 오답 수** 순으로 등수를 가릅니다.

### 순위표 — 팀 / 개인 / 최단 시간

🏆 버튼(또는 대기 화면·결과 화면)에서 봅니다.

| 탭 | 정렬 | 내용 |
|---|---|---|
| 🏅 **팀 순위** | 합계 점수 · 1인 평균 · 최단 시간 | 팀원 점수를 **모두 더한 값**이 팀 점수입니다 |
| 👤 **개인 순위** | 점수순 · 최단 시간순 | 개인 점수와 총 소요 시간 |

- 인원이 3명인 팀과 4명인 팀이 섞이면 합계가 불리할 수 있어 **1인 평균** 정렬을 함께 넣었습니다.
  시상은 둘 중 어느 쪽으로 해도 되고, 화면에서 바로 바꿔 볼 수 있습니다.
- 결과 발표 화면의 시상대는 **팀 기준**이고, 그 아래에서 개인 탭으로 넘길 수 있습니다.

### 출제 규칙 — 팀에 SR3·S1L 이 모두 있어야 탈출합니다

한 방에서 출제되는 3문제의 구성은 **항상** 아래와 같습니다.

| | 문제 | 어떤 문제인가 |
|---|---|---|
| ① | **근무지 전용 1문제** | 그 관에 배정된 근무지(SR3 **또는** S1L) 사람만 답을 압니다 |
| ② | **고난도 1문제** (`tier:'hard'`) | 자료 두세 장을 **확대해서 조합**해야 풀립니다. 배점 10,000점 |
| ③ | **일반 1문제** | 화면·액자를 보면 바로 풀립니다. 배점 6,000점 |

- 관마다 배정 근무지가 번갈아 정해지고, **팀 번호에 따라 순서가 뒤집힙니다.**
  → 어떤 팀이든 4개 관을 돌면 **SR3 전용 2문제 + S1L 전용 2문제**를 반드시 만납니다.
- 근무지 전용 문제에는 퀴즈 창에 `🏢 SR3 근무자만 아는 문제` 배지가 뜹니다.
- 그래서 **팀에는 SR3·S1L 인원이 반드시 섞여 있어야** 합니다.
  관리자의 🎲 랜덤 팀 구성은 두 근무지를 각각 팀에 돌려 담아 이 조건을 보장하고,
  한쪽 근무지만 있는 팀이 생기면 결과 표에 ⚠ 로 표시합니다.

### 🔎 자료(문서) 시스템 — 온라인 방탈출처럼 푸는 장치

방 안의 **게시물·상자·서랍·펜꽂이**를 누르면 계획표·지침 액자·좌석 배치도 같은
**자료**가 나옵니다. 자료 창에서는

- **확대 / 축소** (➕➖ · 마우스 휠) 와 **드래그로 이동**
- 자료가 여러 장이면 **위쪽 탭으로 넘기기** — 두 장을 오가며 조합
- **🔦 UV 램프** — 자료에 형광 잉크로 숨겨 둔 글씨가 램프 안에서만 드러납니다

고난도 문제는 이 자료들을 조합해야만 풀립니다.
예를 들어 1관은 **지침 액자에서 규칙 → 당직 배정표에서 오늘 당직자(UV로 요일 확인)
→ 좌석 배치도에서 그 사람의 자리·사번** 을 거쳐야 문서함 번호가 나옵니다.

### 문제 입력 방식

| `type` | 화면 | 쓰는 곳 |
|---|---|---|
| `short` | 한 칸 주관식 | 일반 문제 대부분 |
| `choice` | 객관식 버튼 | — |
| `multi` | **여러 칸** (예: 좌석번호 + 사번) | 자료 두 장에서 얻은 값을 이어 붙일 때 |
| `order` | **순서대로 클릭해 배열** | 장비 기동 순서, 모니터 켜는 순서 |
| `grid` | **배치도에서 칸 하나 선택** | 시편 트레이 좌표 찾기 |
| `lock` | **회전 다이얼 자물쇠** | 금고·서랍 네 자리 번호 |

정답을 맞히면 **색종이가 날리고 「정답!」 도장**이 찍히며, 틀리거나 함정에 걸리면
**화면이 붉게 번쩍이며 흔들립니다.**

### 문제 종류

| 종류 | 예 | 푸는 방법 |
|---|---|---|
| 화면 관찰 | 명패의 팀 이름, 전광 시계, 그래프 이름 | 방 배경 그림을 살펴봅니다 |
| **자료 읽기** | 당직표에서 야간 당직을 두 번 서는 사람 찾기 | 자료 한 장을 꼼꼼히 읽습니다 |
| **고난도 · 자료 조합** | 지침 + 당직표 + 좌석표 → 문서함 번호 | 자료 두세 장을 오가며 규칙을 적용합니다 |
| **고난도 · UV 램프** | 취소된 회의를 찾아내야 나오는 캐비닛 코드 | 자료에 램프를 비춰 숨은 글씨를 찾습니다 |
| **근무지 전용 (지형지물)** | SR3 사무실 출입문 안쪽 보안 스티커가 붙은 순서 | 그 사이트 근무자가 직접 봐야 압니다 |
| **근무지 전용 (보물찾기)** | S1L 사무실 냉장고 안에 넣어 둔 카드의 낱말 | 운영자가 미리 넣어둔 카드를 찾아옵니다 |

## 4. 관리자 사용법

로그인 화면의 **👑 관리자 로그인** → 비밀번호 입력.

**서버에 처음 로그인할 때 입력한 비밀번호가 그대로 관리자 비밀번호로 고정됩니다.**
(비밀번호의 해시가 `v2/config/adminKey` 에 한 번만 기록되고, 이후에는 그 값과 맞는 사람만 관리자가 됩니다.
코드 어디에도 비밀번호를 적어 두지 않습니다 — 저장소는 누구나 볼 수 있기 때문입니다.)

> 비밀번호를 바꾸려면 Firebase 콘솔 → 데이터 탭에서 `v2/config/adminKey` 를 지운 뒤
> 새 비밀번호로 다시 로그인하세요. 그 사이에는 아무나 첫 로그인으로 관리자가 될 수 있으니 바로 이어서 하세요.

관리자 패널(👑 버튼)에서 할 수 있는 것:

- **🧪 행사 준비 점검** — 실제 서버에 요청을 넣어 보고 규칙 게시·배점표·기록 보호가
  살아 있는지 확인합니다. 관리자 로그인 직후 자동으로 한 번 돌고, 문제가 있을 때만 알립니다.


- 🚀 **게임 시작** — 전원을 1관으로 보내고 타이머 시작
- ➡ **다음 방 열기** / ⬅ **이전 방** — 진행 통제
- ⏸ **일시정지 / 재개** — 멈춘 시간은 제한시간에서 제외됩니다
- 🏠 **전원 대기실로**
- 🧹 **현재 방 리셋** — 그 방의 모든 참가자 진행 기록만 삭제하고 타이머 재시작
> 관리자에게는 방을 마쳤을 때 뜨는 **점수 창을 띄우지 않습니다.**
> 참가자 현황과 점수는 관리자 패널의 표에서 실시간으로 확인하세요.

- 🎲 **랜덤 팀 구성** — 아래 규칙에 맞춰 자동 배분, CSV 저장
  - 한 팀은 **최소 3명** (2명짜리 팀은 만들지 않음)
  - 되도록 **3명**으로 나누고, 나머지가 생길 때만 **4명**
  - 3명 팀 = `SR3 2 + S1L 1` 또는 `SR3 1 + S1L 2`
  - 4명 팀 = `SR3 2 + S1L 2`
  - 즉 **한 팀에 같은 근무지가 2명을 넘지 않습니다** (= 어느 팀에나 SR3·S1L 이 함께 있습니다)
  - 방마다 **근무지 전용 문제**가 나오므로, 한쪽 근무지만 있는 팀은 탈출할 수 없습니다
  - 한쪽 인원이 다른 쪽의 **2배를 넘으면** 이 규칙을 지킬 수 없습니다.
    (예: SR3 30명 : S1L 10명) 이 경우 최소 3명만 보장하고 **경고를 표시**합니다
- ✏️ **팀 편집 · 이동** — 참가자별 드롭다운으로 팀을 직접 바꿀 수 있습니다.
  **대기 중에도, 게임 진행 중에도** 가능하며 바꾸는 즉시 그 참가자에게 적용됩니다
- 🏁 **결과 발표**
- 🔄 **전체 데이터 초기화** — 참가자·기록·팀 전부 삭제하고 참가자를 로그인 화면으로 보냄
  (**관리자는 로그아웃되지 않습니다.** 관리자 로그아웃은 패널 맨 아래 버튼으로만)
- 👥 **참가자 실시간 현황** — 접속 여부 / 근무지 / 이름 / 현재 방 / 푼 단서 / 점수 / 시간

관리자가 F5 를 눌러도 권한과 화면 위치가 그대로 유지됩니다.

## 5. 팀과 문제 출제

- 팀은 서버(`teams` 노드)에 저장되고, 참가자는 **기기마다 발급된 고유 ID** 로 팀을 찾습니다.
  따라서 **튕겼다가 다시 들어와도, 이름을 바꿔 다시 로그인해도 같은 팀으로 복귀**합니다.

### 고치기 전에 — 브랜치를 main 과 맞추세요

이 저장소에서 났던 사고는 대부분 **여러 브랜치가 같은 파일을 따로 고친 것**이 원인이었습니다.
작업을 시작하기 전에 항상:

```bash
git fetch origin main && git merge origin/main
node tools/check-all.js          # 배포 전 한 번에 점검
```

`check-all.js` 는 브랜치가 main 보다 뒤처졌으면 **거기서 멈춥니다.**
자세한 규칙은 `CLAUDE.md` 에 적어 두었습니다.

> **git 충돌이 안 났다고 안심하면 안 됩니다.** 실제로 이런 일이 있었습니다 —
> 한쪽은 `points = 배점 + 속도점수` 로 바꾸고, 다른 쪽은 서버 규칙에
> `points === 배점` 을 넣었습니다. 글자가 안 겹쳐서 git 은 조용히 합쳤지만,
> 그 뒤로 정답 기록이 전부 거부돼 점수·단서 표시·다음 방 버튼·기믹이 한꺼번에 멈췄습니다.
> **main 을 합친 뒤에는 새로 들어온 코드를 직접 읽어 뜻이 맞는지 확인하세요.**

### 점수가 안 오를 때 — 서버 규칙과 배점표

정답 기록(`runs/<uid>/rooms/<방>/solves/<칸>`)은 서버 규칙이 이렇게 검사합니다.

| 항목 | 규칙이 요구하는 것 |
|---|---|
| `points` | **서버에 올라간 배점표(`bank/scores`) 값과 정확히 같아야 합니다** |
| `speed` | 있으면 0~1500 사이의 수 |
| `at` | 서버 시각 |

서버가 기록을 거부하면 참가자 화면에 **「⚠️ 정답이지만 서버가 기록을 거부했습니다. 진행자에게 알려주세요!」** 가
뜹니다 (예전에는 "정답!" 이라고만 뜨고 점수는 0 이라 원인을 찾기 어려웠습니다).
이 경고가 보이면 관리자 패널 → 🧪 행사 준비 점검부터 여세요.

`points` 에 속도 점수를 더해 보내면 **기록이 통째로 거부**되고, 그러면
점수도 · 상단 단서 표시도 · 「다음 방」 버튼 숫자도 · 앞 단서를 요구하는 기믹
(2관 계산기)도 **전부 멈춥니다.** 그래서 코드는 `points` 에 문제 배점만 적고
속도 점수는 `speed` 로 따로 적습니다. 합계는 `NET.scoreOf` 가 더합니다.

**배점을 바꿨다면 서버 배점표도 다시 올려야 합니다** — 관리자로 다시 로그인하면
자동으로 올라갑니다. 관리자 패널 → **🧪 행사 준비 점검** 에서 「문제 배점표 등록됨」 이
✅ 인지 꼭 확인하세요. ❌ 이면 그 상태로는 아무도 점수를 못 얻습니다.

### 배포할 때 — 캐시 버전을 꼭 올리세요

`index.html` 은 스크립트를 `boot.js?v=20260914a` 처럼 불러옵니다.
**이 `?v=` 값을 안 바꾸면 참가자 브라우저는 예전에 받아둔 파일을 계속 씁니다.**
고친 내용이 화면에 안 나타나는 원인의 대부분이 이것입니다.

```bash
node tools/check-cache.js      # 밀렸는지 점검 (배포 전 필수)
sed -i 's/v=20260914a/v=<오늘날짜>a/g' index.html
```

`check-cache.js` 는 `?v=` 값을 마지막으로 바꾼 커밋 이후에 js·css 가 바뀌었으면
어떤 파일이 바뀌었는지 알려주고 종료 코드 1 로 끝납니다.

### 다시 들어올 때 — 근무지 잠금

팀이 짜인 뒤에 근무지를 바꿔 들어오면 그 팀의 SR3·S1L 균형이 깨져
**그 팀 전체가 근무지 전용 문제를 못 풉니다.** 그래서 배정 후에는 근무지를 잠급니다.

| 어떻게 들어왔나 | 무엇이 일어나나 |
|---|---|
| **같은 기기** (로그아웃 후 재입장, F5, 튕김) | 고유 ID 로 팀을 찾아 근무지를 원래대로 되돌리고 `🔒 근무지는 바꿀 수 없습니다` 창을 띄웁니다. **이름은 바꾼 대로 유지**됩니다 |
| **다른 기기·브라우저** (PC → 휴대폰 등) | 기기가 다르면 고유 ID 도 달라집니다. 팀 명단에 **같은 이름**이 있으면 `🔄 이어서 하시겠습니까?` 로 물어보고, 「네」 를 누르면 **이전 ID 를 그대로 이어받아** 점수·팀·근무지가 유지됩니다 |
| 위에서 「아니요, 다른 사람입니다」 | 입장을 막고 다른 이름을 쓰도록 안내합니다 (동명이인 보호) |
| **팀 구성 전** | 아무 제약 없이 근무지를 바꿀 수 있습니다 |
| **이름도 바꾸고 기기도 바꾼 경우** | 찾을 방법이 없습니다. 관리자 패널 → 참가자 현황 → ✏️ 로 고쳐 주세요 |

> 다른 기기에서 이어받는 것이 중요한 이유 — 팀 점수는 **팀 명단의 고유 ID** 로 합산합니다.
> 이어받지 않으면 새 ID 로 쌓인 점수가 **팀 합계에 들어가지 않습니다.**
- 각 방의 3문제는 **팀 번호를 시드로** 문제은행 5개 중에서 뽑습니다.
  → **같은 팀은 항상 같은 문제**, 다른 팀은 다른 조합이 나옵니다 (컨닝 방지).
- 팀이 없는 참가자는 개인 고유값으로 출제되므로 혼자 다른 문제를 풉니다.
  행사 전에 **관리자가 팀을 구성해두는 것을 권장**합니다.
- 관리자가 팀을 옮기면 그 참가자의 **아직 못 푼 문제**가 새 팀 기준으로 바뀝니다.
  이미 맞힌 문제의 점수는 그대로 유지됩니다.
- 참가자는 팀을 스스로 바꿀 수 없습니다. 화면 상단에 자기 팀 번호만 표시됩니다.

### 팀 구성이 되는 인원 · 안 되는 인원

규칙은 **3명 팀 (SR3 2:S1L 1 또는 1:2), 부득이하면 4명 팀 (2:2)** 입니다.
`node tools/check-teams.js` 로 전 인원 조합을 한 번에 점검할 수 있습니다.

```
node tools/check-teams.js          1~48명 전부
node tools/check-teams.js 40       40명일 때 근무지 구성별로
node tools/check-teams.js 14 26    SR3 14 : S1L 26 한 경우만
```

| 상황 | 결과 |
|---|---|
| 적은 쪽 근무지가 **전체의 1/3 이상** | ✅ 규칙대로 배정 |
| 많은 쪽이 「적은 쪽 × 2」 에서 **딱 1명 모자라거나 남을 때** | ⚠️ **4명 팀 하나만** (1:3), 나머지는 규칙대로 — 자동 처리 |
| 많은 쪽이 「적은 쪽 × 2 + 2」 이상 | ⚠️ 섞을 수 있는 만큼만 섞고, **남는 인원은 같은 근무지끼리 3~4명 팀** |
| 한쪽 근무지가 **0명** | ⚠️ 전 팀이 한 근무지 — 그 근무지 전용 문제만 나옵니다 |
| 참가자 **3명 미만** | ❌ 팀을 만들 수 없음 (유일하게 진행 불가) |

**40명일 때** — SR3 가 **14~26명**이면 규칙대로입니다. 13명·27명이면 4명 팀 하나가 (1:3) 이 됩니다.

**게임이 멈추지는 않습니다.** 전용 문제는 **그 팀에 실제로 있는 근무지 것만** 출제됩니다
(`game.js` 의 `solvableSite`). 그래서 한 근무지만 있는 팀이 생겨도 못 푸는 문제는 나오지 않습니다.

| 팀 구성 | 4개 관에서 나오는 전용 문제 |
|---|---|
| SR3 + S1L 섞인 팀 | S1L → SR3 → S1L → SR3 (번갈아, 원래 설계) |
| S1L 만 있는 팀 | 4관 모두 S1L 전용 |
| SR3 만 있는 팀 | 4관 모두 SR3 전용 |

쏠린 인원에서도 **팀 크기는 3~4명으로 유지**됩니다. 예) SR3 5 : S1L 35 → 13팀
(섞인 팀 5개 + S1L 만 있는 팀 8개), 모두 3~4명.

❌·⚠️ 인 경우 관리자 화면에 **왜 그렇게 됐는지**가 표시되고, ✏️ 팀 편집에서 손볼 수 있습니다.

### 근무지는 팀 배정 뒤에 바꿀 수 없습니다

- 참가자가 로그아웃 후 다시 들어올 때 **이름은 바꿀 수 있지만**,
  이미 팀에 배정돼 있으면 **근무지 선택이 잠기고** 경고창이 뜹니다.
  (근무지를 바꾸면 그 팀이 전용 문제를 못 풀게 되기 때문입니다)
- 정말 고쳐야 하면 **관리자 패널 → 참가자 현황 → ✏️** 에서
  이름·근무지·팀을 함께 고칩니다. 팀 명단도 자동으로 따라 바뀝니다.

## 6. 내용 수정하기

거의 모든 내용은 **`assets/js/data.js`** 한 파일에 모여 있습니다.

| 항목 | 위치 |
|---|---|
| 제한시간, 감점/보너스 | `CONFIG` |
| 플레이어 캐릭터 8종 | `AVATARS` |
| 각 방 파트장님 | `BOSSES` |
| **크레도 문구 (정답 자동 계산)** | `CREDO` |
| **자료 (계획표·지침·배치도)** | `DOCS` |
| **문제은행 (방마다 6문제)** | `BANK` |
| 방 배치 · 기믹 · 낚시 소품 | `ROOMS` |

문제 형식:
```js
{ id: 'r1q1', type: 'choice', score: 6000,
  q: '질문', choices: ['1번','2번','3번','4번'], ans: 1,   // ans = 0부터 시작
  ok: '정답 시 파트장님 대사' }

{ id: 'r1q5', type: 'short', score: 7000,
  q: '질문', hint: '힌트', ans: ['정답', '허용답안2'],       // 띄어쓰기·대소문자 무시
  ok: '정답 시 대사' }

// 근무지 전용 문제 : loc 만 붙이면 됩니다 ('SR3' 또는 'S1L')
{ id: 'r1sr3', loc: 'SR3', type: 'short', score: 8000, q: '...', ans: ['2'],
  note: '★확인필요 : 실제 대수로 고칠 것',   // note 는 운영자 메모용, 게임에는 안 쓰임
  ok: '...' }

// 크레도 문제 : ans 대신 credo 를 쓰면 정답이 자동으로 계산됩니다
{ id: 'r1c3', type: 'short', score: 7000, q: '...', credo: { pick: [[2,1],[4,-1]] }, ok: '...' }
```

**방마다 6문제의 구성은 `SR3 전용 1 + S1L 전용 1 + 고난도 2 + 일반 2` 로 맞춰주세요.**
(한 종류라도 비면 출제가 안 되고, 브라우저 콘솔에 경고가 찍힙니다.)

### ★ 자료(DOCS) 고치기

`assets/js/data.js` 의 `DOCS` 가 자료 한 장씩입니다. 표 내용만 바꿔도 그대로 반영됩니다.

| `kind` | 생김새 | 필요한 값 |
|---|---|---|
| `frame` | 액자·지침문 (번호 매긴 줄) | `lines: []` |
| `note` | 손으로 쓴 메모 | `lines: []` |
| `table` | 표 | `cols: []`, `rows: [[]]` (첫 칸은 굵게) |
| `seats` | 격자 배치도 | `rows`, `cols`, `cells: { B3: { name, no } }` |
| `labels` | 라벨 목록 | `items: [{ k, v }]` |

- `uv: [{ x, y, text }]` 를 넣으면 그 글씨는 **🔦 UV 램프를 켜야만** 보입니다 (x·y 는 종이 기준 %).
- `from: 'credo'` 로 두면 `CREDO.lines` 를 그대로 보여줍니다.

### ★ 크레도 문구 넣기 — 정답은 자동 계산됩니다

`assets/js/data.js` 의 `CREDO.lines` 를 **사무실 벽에 걸린 실제 크레도 문구**로
줄 단위로 바꾸면, 크레도 문제 4개의 정답이 저절로 다시 계산됩니다.
**정답을 따로 고칠 필요가 없습니다.**

```js
const CREDO = {
  title: '분석기술팀 크레도',
  lines: [
    '우리는 데이터로 말한다',        // 1줄  ← 여기를 실제 문구로 교체
    '정확한 분석이 신뢰를 만든다',    // 2줄
    ...
  ]
};
```

`credo` 에 쓸 수 있는 형식 (글자 위치는 1부터, 음수는 뒤에서부터. 띄어쓰기는 세지 않음):

| 쓰는 법 | 뜻 | 예시 정답 |
|---|---|---|
| `{ word: [2,1] }` | 2줄의 첫 낱말 | `정확한` |
| `{ word: [-1,-1] }` | 마지막 줄의 마지막 낱말 | `완성된다` |
| `{ count: '우리' }` | 크레도 전체에서 그 낱말이 나온 횟수 | `2` |
| `{ len: 3 }` | 3줄의 글자 수 | `12` |
| `{ lineCount: true }` | 크레도 전체 줄 수 | `6` |
| `{ pick: [[2,1],[4,-1]] }` | 2줄 첫 글자 + 4줄 마지막 글자 | `정다` |

> **되도록 `word` 를 쓰세요.** 글자를 뽑아 붙이는 `pick` 은 정답이 `정다` 처럼
> 뜻 없는 글자 묶음이 되어, 참가자가 맞게 입력했는지 확신하지 못합니다.
> `word` 는 크레도 문구를 무엇으로 바꾸든 **늘 뜻이 있는 낱말**이 정답이 됩니다.
>
> **난이도는 정답이 아니라 「정답까지 가는 단계」로 주세요.**
> 몇 번째 줄인지를 문제에 그냥 적어 주면 한 번 읽고 끝나지만,
> 줄 번호를 방 화면에서 세어야 알 수 있게 하면 두 단계짜리 문제가 됩니다.
> (예: `r1e1` — 명패의 팀 이름 글자 수 5 → 크레도 5번째 줄의 첫 낱말)

> 줄 수가 모자라 정답을 못 만들면 브라우저 콘솔에
> `[S1FA] 크레도 문제 정답 없음: r1c3` 경고가 뜹니다. 게임 시작 전 F12 로 한 번 확인하세요.
> 크레도가 SR3·S1L 에 서로 다르게 걸려 있다면, 그 문제에 `loc` 을 붙여 근무지 전용으로 돌리세요.

**`r3sr3` — 벽 비전 문구 문제**

벽 문구는 영문 두 줄 · 초록 선 · 한글 두 줄인데, 영문 중 **`THE MOST TRUSTED` 만 파란색**입니다.
묻는 것은 **그 부분이 영문 몇 자, 한글 몇 자인가** 둘뿐입니다. (띄어쓰기 제외)

| | | |
|---|---|---|
| 영문 | `THE MOST TRUSTED` → `THEMOSTTRUSTED` | 세 낱말 · **14** 자 |
| 한글 | 가장 신뢰받는 → 가장신뢰받는 | 두 낱말 · **6** 자 |
| 정답 | 두 칸을 두 자리씩 | **1406** |

- 같은 뜻인데 **영어 14자 · 한글 6자** — 그 차이가 이 문제의 맛입니다.
- **어디까지가 「그 부분」인지**가 헷갈릴 수 있어, 문제에 **영문 세 낱말 · 한글 두 낱말**이라고
  적어 두었습니다. 세어 본 낱말 수가 다르면 범위를 잘못 잡은 것이니 참가자가 스스로 압니다.
  힌트에도 **뒤에 이어지는 이름씨(회사·파트너 같은 말)는 세지 않는다**고 적었습니다.
- 양쪽 다 **글자 수**로 셉니다. 낱말 수(3·2)는 범위를 확인하는 용도이지 정답이 아닙니다.
- 한 자리 수는 앞에 0 을 붙입니다(`6` → `06`). 게임 안 다른 문제(`0906` 등)와 같은 방식입니다.
- 초록 가로줄은 글자가 아니라 세지 않습니다. 문제 문장에 "글자 색" 이라고 못박아 두었습니다.
- 강조 색이 옮겨가거나 문구가 바뀌면 `ans` 를 함께 고치세요.
- S1L 에도 같은 비전 문구가 붙어 있을 수 있지만, **어디가 강조되어 있고 몇 자인지는 외워지지 않습니다.**

**`r4sr3` — 셀 벽면 줄무늬 문제**

벽면 줄무늬를 **세 가닥의 신호선**으로 봅니다. 줄무늬 벽은 **딱 두 군데에서 끊깁니다** —
**캔틴 룸 입구**(1·2번 판 사이)와 **화장실로 가는 복도 입구**(3·4번 판 사이).
그 두 군데가 벽을 **세 구역**으로 나눕니다.

처음에는 구역을 「왼쪽·가운데·오른쪽」으로 적었는데, **어느 쪽이 왼쪽인지 서는 방향에 따라
달라져** 모호했습니다. 그래서 **캔틴·화장실이라는 실제 지형지물**로 바꿨습니다 —
방향과 상관없이 한 가지로만 읽힙니다. 입력칸 이름도 `캔틴 쪽` · `가운데` · `화장실 쪽` 입니다.

세는 것은 **주황색 선이 다른 선과 엇갈려 지나가는 곳**입니다.

| 구역 | 어디부터 어디까지 | 판 | 주황색 선의 교차 | 상대 |
|---|---|---|---|---|
| 캔틴 쪽 | 캔틴 룸 입구에서 바깥쪽 끝까지 | 1번 (1개) | **1** | 연두 |
| 가운데 | 캔틴 룸 입구 ↔ 화장실 복도 입구 | 2·3번 (2개) | **1** | 파랑 |
| 화장실 쪽 | 화장실 복도 입구에서 바깥쪽 끝까지 | 4·5·6번 (3개) | **2** | 연두 1 · 파랑 1 |

- 힌트에 **판이 캔틴 쪽부터 1개·2개·3개**라고 적어 두었습니다. 세어 본 판 수가 다르면
  구역을 잘못 잡은 것이라 참가자가 스스로 알아챕니다.
- **벽이 어떻게 끊겨 있는지가 SR3 전용 지식**입니다. 벽 사진만 봐서는 캔틴·화장실 자리를 모릅니다.

- 정답 `112` 는 구역별 교차 수를 **캔틴 쪽부터** 이어 붙인 것입니다. 벽 앞에서 한 번 세어 확인하세요.
- 색깔별 총 교차는 **연두 5 · 파랑 5 · 주황 4** (벽 전체 교차점 7군데)입니다.
  같은 벽을 **연두**로 세면 `1·3·1`, **파랑**으로 세면 `0·4·1` 입니다.
  파랑은 캔틴 쪽 구역이 0 이라, 힌트의 "교차가 하나도 없는 구역은 없습니다" 와 어긋나 쓰지 않습니다.
- 한 색의 **총 교차 수만** 물으면 한 자리라 찍힙니다. 그래서 구역별로 나누어 세 자리로 둡니다.
- 층이 몇 번 바뀌었는지가 아니라 **선끼리 엇갈린 곳**을 셉니다. 나란히 가다 멀어지는 것은 교차가 아닙니다.
- 벽이 그림과 다르면 `ans` 의 세 숫자만 고치면 됩니다.

- 문제 문장(`q`)에 자리·물건 이름이 들어 있으니, 사무실 사정에 맞게 자유롭게 바꿔 쓰세요.
- **회전 다이얼(`lock`)** 은 되도록 방마다 하나만 나오게 두었습니다.
  2·4관은 고난도가 다이얼이라 전용 문제를 입력칸으로 두었고, 3관 전용 문제는 순서 배열입니다.
  **1관만 예외**입니다 — 일상점검표 문제를 다이얼로 두었고 고난도 `r1h2` 도 다이얼이라,
  그 둘이 함께 뽑힌 팀은 1관에서 다이얼을 두 번 돌립니다. 기능상 문제는 없습니다.
  피하고 싶으면 `r1h2` 를 `multi`(두 칸 입력)로 바꾸면 됩니다.
- **정답은 뜻이 있는 낱말이나 숫자로 정하세요.** 글자를 이어 붙인 정답(`지인인` 같은)은
  참가자가 맞게 입력했는지 확신하지 못해 오답 감점으로 이어집니다.
  정답끼리 겹치지 않게 하는 것도 좋습니다.

> **주의** — 근무지 전용 문제에 쓰는 표지·스티커는 **게임 안 자료(DOCS)로 넣지 마세요.**
> 화면에서 읽을 수 있게 되는 순간 다른 근무지 사람도 풀 수 있어 전용 문제가 아니게 됩니다.

### 글자·화면 크기

40~50대 참가자도 편하게 볼 수 있도록 전체 글자를 **한 단계 키웠습니다** (가장 작던 9~11px → 12~14px).
채팅의 보낸 사람 이름은 특히 작아서 **14px 굵게**로 따로 키웠습니다.

게임 화면(`#app`)은 최대 **1060px** 이고, 세로가 짧은 화면에서는 **한 화면에 다 들어오도록**
방 그림이 자동으로 줄어듭니다 (`#game-screen` 의 `max-width` 계산).

| 창 크기 | 방 그림 | 세로 스크롤 |
|---|---|---|
| 1920 × 1080 | 1052 × 700 | 없음 |
| 1366 × 768 | 778 × 517 | 없음 |
| 1100 × 820 | 856 × 569 | 없음 |
| 430 × 860 (휴대폰) | 414 × 275 | 없음 |

- 더 키우고 싶으면 `style.css` 의 `#app{max-width:1060px}` 와, 화면이 넘치면 `--chrome-h`(기본 244px)를 함께 조절하세요.
- HUD 는 창 너비가 아니라 **게임 화면 너비**를 기준으로 줄어듭니다(`@container hud`).
  좁아지면 방 이름이 「2관 · EFA2」 처럼 짧게 바뀝니다.
- 순위표는 620px 아래에서 부차적인 열(근무지 · 1인 평균 · 단서)을 접습니다.

**눌러볼 수 있는 자리에는 작은 회색 점이 찍힙니다.**
배경이 사진처럼 복잡해서 어디를 눌러야 할지 모르면 5분 안에 못 풉니다.
그렇다고 단서에만 표시하면 답을 알려주는 꼴이라, **단서 · 낚시 · 자료를 모두 같은 점**으로 찍습니다.
→ *어디를 눌러 볼 수 있는지*는 알지만, *어느 게 진짜 단서인지*는 직접 눌러 봐야 압니다.
(2관이면 점 8개 중 단서는 3개, 나머지 5개는 낚시와 자료입니다. 푼 단서는 초록으로 바뀝니다)

**한참 헤매면 그때 도와줍니다.** 방에 들어온 지 `CLUE_HINT_AT` 초(기본 180초)가 지나면
아직 못 푼 **단서 자리만 금색으로** 바뀌고 안내 문구가 뜹니다.

| 설정 (`data.js` 의 `CONFIG`) | 기본값 | 뜻 |
|---|---|---|
| `SPOT_DOTS` | `true` | `false` 로 두면 아무 표시도 하지 않습니다 (순수 탐색) |
| `CLUE_HINT_AT` | `180` | 이 초가 지나면 남은 단서만 금색. `0` 이면 끝까지 안 알려줍니다 |

**치우는 소품(포스트잇 · 서류 더미 · 공지문)은 SVG 그림입니다.**
`game.js` 의 `PROP_ART` 에 들어 있습니다. 배경 그림을 바꿔서 소품이 겉돌면 여기를 고치세요.

#### (참고) 스크린샷에서 캐릭터 뽑아내기
확대되어 찍힌 도트 그림을 원래 해상도로 되돌리고 배경을 지워주는 도구입니다.
```bash
pip install pillow numpy
python3 tools/extract-sprite.py 스크린샷.png \
    --box 215,1440,475,1895 \
    --floor 520,1600 \
    --out assets/img/char/p1.png
```
- `--box` 캐릭터 주변을 넉넉히 감싼 영역 `x0,y0,x1,y1`
- `--floor` 캐릭터가 없는 **깨끗한 바닥** 한 지점 `x,y` (여기 색을 배경으로 보고 지웁니다)

### 캐릭터 도트를 직접 고치고 싶다면
`assets/js/sprites.js` 는 **문자 하나 = 픽셀 하나**인 32×48 그리드입니다.

```js
PX.setCharImage('jihun', 'assets/img/char/jihun.png');   // 32x48 비율 권장
// data.js 의 AVATARS 항목에 sprite: 'jihun' 추가
```

### 방 담당자(파트장님) 위치 조정
방마다 담당자가 한 명씩 서 있고, 누르면 **아직 남은 단서를 알려줍니다.**

## 8. 잘 안 될 때

### ⚠️ 기능이 늘어나면 규칙도 다시 게시해야 합니다

`database.rules.json` 은 기능이 추가될 때마다 항목이 늘어납니다.
(예: 채팅이 들어가면서 `chat` 항목이 추가되었습니다.)
**예전에 게시한 규칙만 올라가 있으면 새로 생긴 경로만 접근이 막힙니다.**

- 채팅만 막힌 경우 → 게임 화면에 `💬 채팅만 사용할 수 없습니다` 창이 뜨고,
  채팅 버튼이 숨겨집니다. **게임 진행과 점수 기록은 정상입니다.**
- 이때는 `node tools/print-rules.js` 결과를 Firebase 콘솔 → Realtime Database →
  **규칙** 탭에 다시 붙여넣고 **[게시]** 한 뒤 새로고침하세요.

어디가 막혔는지는 안내 창의 **거부된 경로** 와
F12 → Console 의 `[S1FA] 실시간 구독 실패 (경로)` 메시지로 알 수 있습니다.

### 버튼을 눌러도 아무 반응이 없다
거의 대부분 **Firebase 데이터베이스 접근이 거부된 경우**입니다.
새로 만든 Realtime Database 는 기본값이 "모든 접근 차단" 이라, 규칙을 게시하기 전에는
읽기·쓰기가 전부 막혀 있습니다.

1. 브라우저에서 **F12 → Console** 을 엽니다.
2. `PERMISSION_DENIED` 또는 `[S1FA] Firebase 접근 실패` 가 보이면 규칙 문제입니다.
3. Firebase 콘솔 → Realtime Database → **규칙** 탭에 `database.rules.json` 파일 내용을
   그대로 붙여넣고 **게시**하세요.

급하게 확인만 하고 싶다면 아래 규칙으로 먼저 열어두고 테스트한 뒤,
행사 전에 반드시 `database.rules.json` 으로 바꾸세요.
```json
{ "rules": { ".read": true, ".write": true } }
```

### 그 밖의 확인 사항
- `assets/js/net.js` 의 `firebaseConfig` 가 **내 프로젝트 값**인지
- `databaseURL` 의 지역(`asia-southeast1` 등)이 실제 DB 와 같은지
- 콘솔에 `404 assets/img/char/*.png` 가 뜨는 건 **정상**입니다 (아직 안 넣은 캐릭터 그림)

서버에 못 붙어도 게임 화면은 열리지만, **점수·시간이 저장되지 않고 다른 참가자와
동기화되지 않습니다.** 이 경우 화면에 경고 창이 뜹니다.
